# Unity / Godot 框架建设目标

以可运行的共享逻辑、引擎适配和自动验收推进，Unity 与 Godot .NET 为近期宿主。其他引擎与语言保留清晰的契约边界，不将尚未实现的适配记为支持。

## 本轮已完成

- [x] 修复 Unity 暂停恢复、对象池重复交付、配置驱动和异步 UI 竞态。
- [x] 实例化 GameHost：独立服务、异步模块依赖、回滚、取消、暂停恢复与主线程调度。
- [x] 共享流程与 Unity / Godot / Headless 示例：配置 → 菜单 → 关卡 → 存档 → 重启恢复。
- [x] 配置源校验、强类型生成、结构版本与生成结果检查。
- [x] 版本化存档、迁移链、原子封装、备份和损坏恢复。
- [x] 资源所有权、取消与释放；UI 状态和生命周期管理。
- [x] 可选网络、错误/超时/取消和会话边界；协议契约生成。
- [x] 双引擎编译/运行与构建入口、版本/产物报告和结构化生命周期诊断。

2026-10-19 本机验收：通用层 231 项测试通过；Unity 2022.3.16f1 的 29 项真实对象断言、共享 PlayMode 和 Windows Mono Player 构建运行通过；Godot 4.5.2 .NET 编译、原生运行、Windows debug 导出运行通过。三种宿主执行同一共享流程。命令与边界见 [验证说明](validation.md)，旧 API 的迁移见 [迁移说明](migration.md)。

## 后续按产品需求接入

- [ ] 资源发布清单、校验、增量下载、断点续传、版本回退与引擎后端；现有租约层没有 LRU/内存预算，Godot 后端目前同步加载。
- [ ] 完整场景/页面接入、转场、焦点与输入路由、原生视图创建/销毁；现有导航栈负责状态历史与流程生命周期，示例负责原生界面。
- [ ] 接入实际服务端协议，验证登录/登出、幂等操作、推送补查、长连接及断线恢复；现有 HTTP 包不隐式重试。
- [ ] 按平台接入账号、支付、广告、分析、崩溃上报与云存档；实现产品存档 DTO 和旧格式导入策略。
- [ ] Unity IL2CPP/AOT、移动端前后台、Web/其他导出目标的构建与设备验证；补齐 Unity 许可证 CI，取得新增 Godot Linux CI 的实际运行结果。
- [ ] 依据玩法补充战斗、任务、背包、数值等业务模块，以及有需求的代码热更新；将旧静态管理器逐步迁移到实例 API。

这些工作需要对应的产品、服务端或目标平台约束。涉及平台能力时记录真实导出与运行结果，不用编辑器编译替代发布验证。

长期目标包括其他语言；优先复用数据定义、协议和兼容性规则，再选择桥接或原生实现。
