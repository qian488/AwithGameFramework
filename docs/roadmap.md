# Unity / Godot 框架建设目标

以可运行的共享逻辑、引擎适配和自动验收推进，Unity 与 Godot .NET 为近期宿主。其他引擎与语言保留清晰的契约边界，不将尚未实现的适配记为支持。

## 已有基础

- [x] 修复 Unity 暂停恢复、对象池重复交付、配置驱动和异步 UI 竞态。
- [x] 实例化 GameHost：独立服务、异步模块依赖、回滚、取消、暂停恢复与主线程调度。
- [x] 共享流程与 Unity / Godot / Headless 示例：配置 → 菜单 → 关卡 → 存档 → 重启恢复。
- [x] 配置源校验、强类型生成、结构版本与生成结果检查。
- [x] 版本化存档、迁移链、原子封装、备份和损坏恢复。
- [x] 资源所有权、取消与释放；UI 状态和生命周期管理。
- [x] 可选网络、错误/超时/取消和会话边界；协议契约生成。
- [x] 双引擎编译/运行与构建入口、版本/产物报告和结构化生命周期诊断。

Unity、Godot 和 Headless 执行同一共享流程。各轮的实际测试结果、构建与运行范围见 [验证说明](validation.md)，旧 API 的迁移见 [迁移说明](migration.md)。

## 2026-10-27 框架收敛

AgentKit 后续开发暂缓，优先处理游戏框架本身：Godot 每树退出所有权及启动期暂停、旧单例并发、持久化会话配置、视图/场景句柄权限、HTTP 正文上限。现代 Unity、兼容服务、DOTween 和 SQLite 分为独立包，实例模块由静态检查约束；视图布局按纯规则与服务编排分层。范围和兼容性变化见 [迁移说明](migration.md)，实际运行记录见 [验证说明](validation.md)。

## 开发期 Agent 工程基础（2026-10-27）

提供模型无关的 `AgentKit`：任务范围与脏工作区基线、按需上下文及预算、固定工具目录、具体计划与确认、验证结果/日志/耗时、机器检查和人工评审分离，以及本地事件监看。复用任务、评审、交接文档和可编译的 Domain/Application 功能模板，标准验证同时检查工具契约、回归和模板。入口见 [AgentKit](../agent/README.md)。

这层负责辅助人类与现有 AI 工具协作，未接入特定模型 SDK、自动玩法生成、线上 LLM 质量/费用监控、远程执行或 OS 沙箱。具体玩法仍按后续真实需求实现；当前本机验证证据见 [验证说明](validation.md)。
