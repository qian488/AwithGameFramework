# 框架能力与后续方向

近期宿主为 Unity 与 Godot .NET，共享逻辑通过 Headless 与真实引擎样例持续验证。下表描述当前实现范围，具体平台和源码状态以[验证基线](validation/latest.md)为准，不把可扩展边界当成所有引擎都已支持。

## 已有运行时基础

| 领域 | 当前能力 |
| --- | --- |
| 宿主与流程 | 实例 GameHost、独立服务/事件、显式异步模块依赖、启动回滚、取消、暂停恢复、主线程调度、FlowMachine 与导航 |
| 时间与对象池 | 缩放/未缩放游戏时间、一次/重复定时器、Delay、停止清理；普通 C# 对象池的预热、容量、借还所有权与租约 |
| 展示与交互 | 视图层级、模态、焦点、输入路由、显式属性绑定、Single/Additive 场景所有权和失败清理；Unity/Godot 后端 |
| 输入与音频 | 动作/上下文/重绑、按下/保持/释放、UI 优先消费、失焦释放；音量分组、并发/循环/暂停与资源回收 |
| 本地化与设置 | 实例语言/父语言/默认回退、文本绑定、统一语言/音量/按键恢复、设置保存竞态与关闭重试 |
| 数据与存档 | 持久化与真实编解码器契约、严格选项拒绝；版本化存档迁移链、原子封装、备份、checksum 与损坏恢复 |
| 配置与协议 | 可审查 schema、枚举/列表/嵌套结构、UTF-8 JSON/CSV、强类型生成、结构校验及兼容性基线 |
| 资源与内容 | 资源 scope/共享加载/取消清理、有限空闲 LRU/预加载；AssetBundle/PCK 构建、发布、HTTP 校验下载/续传与原子版本激活 |
| 可选网络 | HTTP 错误/超时/取消、正文大小限制与会话隔离；WebSocket 心跳/有限重连/显式连续推送恢复契约，localhost 真实连接测试 |
| 适配与演示 | 现代 Unity、独立旧兼容服务与 DOTween/SQLite 包；Godot .NET；两端和 Headless 共用的完整交互应用 |
| 可维护性 | 纯设置与布局规则、命令式应用服务、实例/兼容边界检查、包元数据/GUID 检查、生成结果检查与结构化生命周期诊断 |

Godot 宿主实现每树退出协调和启动期暂停回放。持久化会话捕获配置，视图/场景句柄保持服务清理权限，旧单例有同步保护。旧全局 API 仍独立于实例宿主，迁移契约见[迁移指南](migrations/README.md)。

这些能力有明确边界：缓存预算仅统计空闲资产的后端估算；Godot PCK 属于进程挂载，不能卸载或替换同 namespace；内容链分发原始文件和已构建引擎资源；推送恢复要求产品实现服务端补查契约。具体接入见各包 README 与[资源流水线](guides/content-pipeline.md)。

## 开发期工具与模板

已有 [AgentKit](../agent/README.md)：任务读写范围与脏工作区基线、模块发现与按模块选择的有限上下文/预算、固定工具目录、具体计划与真实确认、执行日志/耗时、机器检查与人工评审分离、本地事件监看。提供任务/评审/交接模板及可编译的[Domain/Application 功能模板](../templates/portable-feature/README.md)，标准验证包含工具契约、文档本地链接、行为回归和模板。

该层负责辅助人类与现有 AI 工具协作，没有特定模型 SDK、自动玩法生成、线上模型质量/费用监控、远程执行或 OS 沙箱。AgentKit 后续扩展暂缓，优先维护框架基础与实际项目接入。

文档按 architecture（含 decisions）/ guides / reference / migrations / validation / research 分工，旧入口保留导航；当前协作规则以 AGENTS 和局部包说明为来源。仓库结构取舍见[组织调研](research/repository-organization.md)。

## 按产品需求推进

- [ ] Addressables、CDN/清单认证与历史版本磁盘回收；保留当前 AssetBundle/PCK 的明确所有权与版本隔离。
- [ ] 产品页面、加载/转场动画、布局主题、手柄/触屏与目标设备焦点策略、3D/流式音频。
- [ ] 实际服务端登录/登出、业务幂等、推送补查 API 与游标持久化；HTTP 和业务发送继续不隐式重放。
- [ ] 平台账号、支付、广告、分析、崩溃上报与云存档；产品存档 DTO 及旧格式导入。
- [ ] 移动前后台、Web/其他导出目标的设备运行、具体 SDK/AOT 兼容性；Unity 许可证 CI 与 Godot Linux CI 的真实远端证据。
- [ ] 按具体玩法补充战斗、任务、背包、数值和有实际需求的代码热更新；逐步将旧静态管理器迁移到实例 API。

新增工作先明确产品、服务端或目标平台约束和验收范围，再决定是否进入通用框架。涉及平台能力时记录真实构建与运行结果。其他语言优先复用数据、协议和兼容性规则，再选择独立桥接或实现。
