# Unity 程序化资产工作流

`Test` 的 Rain Pass 提供了程序化环境的完整示例。参数资源、生成器和生成结果各自承担不同职责，具体关卡内容留在游戏客户端，通用编辑器事务和验证能力留在 Unity 适配层。

## 两种运行模式

- `RuntimeGenerated` 在运行时按参数和固定种子重建环境，适合天气、战斗特效和动态变化内容。
- `BakedAsset` 读取已保存的 Prefab、材质和纹理，适合需要在 Project 和 Prefab Mode 中持续维护的环境内容。

两种模式应使用同一个生成器和同一份参数资源。这样可以比较运行时重建结果和烘焙结果的布局摘要，并在参数变化后发现过期资产。

## 生成结果

生成结果应放在游戏客户端的内容目录，不进入公共框架包。结果至少包括以下内容。

- 可在 Unity 中打开和修改的 Prefab。
- 生成结果引用的材质和纹理。
- 记录生成器 ID、版本、参数输入哈希和输出路径的 manifest。
- 由生成器附加到根节点的来源标记。

清理和重建只能操作 manifest 登记的输出，避免删除项目手工维护的资源。

## 验证范围

机器验证检查参数哈希、生成输出存在性、来源标记和 Prefab 引用。画面自动验收检查固定取景的截图。构图、材质观感、层次、动效节奏和战斗可读性仍由人工验收决定。

具体操作见 [Test Rain Pass 环境资产工作流](../../games/Test/README.md#环境资产工作流)。
