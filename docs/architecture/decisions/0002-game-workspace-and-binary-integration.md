# ADR 0002：游戏工作区与外部程序集接入

日期：2026-11-02。状态：已采用。依据为[产品方向](../../product-direction.md)，操作步骤见[游戏工作区入门](../../getting-started/game-workspace.md)。

## 背景

仓库已有独立运行时与引擎适配，但示例目录不能清楚表达具体游戏、服务端和共享业务的归属。开发者需要克隆后直接开发游戏，并让框架和可独立的游戏代码留在引擎工程外编译；引擎只容纳必要的原生表现、资源和接线。默认每个游戏独立克隆并选定一个主引擎，同时保留同仓库多个游戏的组织能力。

## 决定

游戏位于 `games/<Name>`，入口清单为 `game.json`。`src/<Name>.Domain` 存放纯规则和普通数据；`src/<Name>.Application` 存放命令式编排与共享模块入口。`server/<Name>.Server` 负责 .NET 进程启动、配置与宿主基础设施；`client/Unity` 或 `client/Godot` 由开发者创建真实工程。游戏配置与协议源分别位于 `configuration`、`protocol`，生成工具按本游戏输入显式接入。

公共 `src` 包不引用具体游戏。Application 可以组合领域与公共运行时；客户端与服务端引用 Application。服务端专用基础设施和引擎类型不进入共享领域项目。外部项目使用游戏名前缀，避免多个游戏在统一构建目录中产生同名输出。

便携代码独立编译为 DLL 与 PDB，构建产物位于 `artifacts/games/<Name>/<Configuration>`。同步命令只更新已创建客户端内由工具拥有的目录，并维护文件清单；引擎工程本身不由脚手架代建。

Unity 使用嵌入式 UPM 分发目录：便携 DLL 加现代 Unity 适配源码。生成副本的 asmdef 将便携程序集改为预编译引用，适配之间和原生 UI 的引用保持原有边界。Newtonsoft.Json 使用 Unity 官方包，避免同时导入 NuGet DLL。Godot 使用 DLL 与生成的 MSBuild `.props`，客户端显式导入；适配由真实 Godot .NET SDK 编译。

## 结果与约束

游戏共享代码可在不启动编辑器时构建，客户端与服务端使用同一份规则。客户端更新通过命令重建和同步产物，不以手工复制 DLL 作为源码依赖。必要的引擎适配源码仍由 Unity 编译，Godot 原生功能仍由 Godot 管理。

同一客户端不能同时使用同名框架程序集的源码包与 DLL。生成目录属于可重建产物，手写代码与第三方插件放在其他位置；Spine、TMP 等由开发者在客户端安装。旧 Unity 可选适配包不在本次自动分发范围内。

DLL 方式需要在源码修改后显式构建、同步，并验证符号、原生导入、AOT 与平台兼容；外部编译不能代替真实引擎运行或导出。现有 `samples` 保持示例和历史验证用途，不迁为实际游戏。该决定落实工作区和接入方式，不代表已提供具体联网业务、生产部署、H5 或 UE5 支持。

本决定补充 [ADR 0001](0001-engine-independent-runtime.md) 的源码依赖边界：框架与游戏开发仍使用项目引用，客户端消费可重建的发布产物；原有源码 UPM 接入作为既有用法保留。
