# BBads 框架能力验证与补强

用 Test 中已经接入的 BBads 跑一局完整战斗，沿同一条流程验证框架运行时、Unity 适配、美术与配置工具，以及 AgentKit 工单交接。用现有场景、鱼猫道具、波次、单位和投射物构造用例。打包、发布、设备专项按此前约定暂缓。

## 已有证据和验证起点

- 迁移报告已有场景及 Prefab 导入、配置、图集、高低档画面和后台战斗证据。本次先在当前工作区复跑可复用的检查，分别记录历史和本次结果。 [迁移验收](../bbads-integration/verification.md)
- 场景入口直接调用 Unity `SceneManager`。曲线中同时存在刷怪计时、召唤充能、攻击和投射物计时。它们目前各有计时入口，适合验证宿主切换、同一暂停语义及回调清理。 [转场入口](../../client/Unity/Assets/BBads/Runtime/UI/BBadsSceneActions.cs)
- 代表资产通过 `Resources` 加载，单位、战斗表现与背包视图已有回收机制。选择真实的单位 Prefab 和共享 Sprite 验证作用域、实例与租约的销毁顺序。 [单位加载入口](../../client/Unity/Assets/BBads/Runtime/Combat/CombatSpawner.cs)
- 现有冒烟覆盖了按钮回调与游戏摆放接口。本次补测射线命中、拖拽事件和焦点丢失经过 Unity 输入路径时的行为。 [当前冒烟入口](../../client/Unity/Assets/BBads/Runtime/BBadsSmokeProbe.cs)

## 完整场景用例

1. 从 `SampleScene` 的 **Open BBads** 进入战斗。验证快速重复点击只启动一次切换。固定现有配置、摆放位置和触发时间，再跑一次默认自动摆放作为对照。
2. 用场景中的 Unity UI 将鱼和猫拖进相邻格，等待充能与召唤。记录波次、充能、在途投射物及伤害事件。同步覆盖非法落点、回到托盘和拖拽取消，核对物品、占格和召唤次数。
3. 在待刷怪、道具充能和投射物飞行同时存在时暂停。以状态断言确认暂停期间的波次、充能、逻辑移动和命中结算。恢复后检查原有进度和事件顺序，每项到期动作结算一次。动画和 UI 的暂停表现按对应时间域核对。
4. 在另一次进入过程中控制真实资源加载结果的交付时点。发起资源请求后退出，随即重新进入，再让旧请求完成。检查旧会话的结果、事件和订阅均已回收，新会话只接收自己的结果。另设一次可重复的场景加载失败，检查返回路径和重试。
5. 走到基地败北，核对结束事件只产生一次且停止刷怪。从现有 Restart 和 Exit 入口跑多轮，记录池峰值、实例、订阅与租约。并行验证一个可完成的时间轴结束用例。
6. 复跑 Rain Pass 与粒子示例，核对 Test 原有入口、宿主接线和外部程序集同步。收集 BBads 的关键状态画面和布局断言。

## 工单及完成条件

详细读写范围、必需检查和验收编号见 [AgentKit 看板](board.json)。基线验收后可并行做六个切片。时间切片负责暂停信号和计时契约，拖拽切片可先独立验证已有输入，最终在集成工单核对两者组合。资源租约与对象池分别验证归还和实例复位，最终在集成工单核对销毁顺序。

| 工单 | 验证与交付 |
| --- | --- |
| `baseline` | 固定 Test 工作区、编辑器版本和所用场景，记录既有行为、自动验证结果和证据路径。 |
| `host-transition` | 通过现有界面入口验证 `GameHost`、`SceneService` 和 `UnitySceneBackend` 接入点，覆盖重复切换、失败、重试、退出和重进。 |
| `resource-leases` | 以真实 Prefab 和 Sprite 验证 `ResourceStore`、`ResourceScope` 及 Unity 加载器。覆盖两个消费者、取消后晚到结果、释放顺序和重新获取。 |
| `time-events` | 用 `GameClock`、调度和事件在原有战斗中验证暂停、恢复、退出和跨会话隔离。 |
| `pool-performance` | 用现有波次和单位、投射物复用路径记录创建、借还、复位、峰值及多轮退出后的数量。性能比较固定配置、时段、运行环境和采样方式。 |
| `drag-input` | 用 Unity `EventSystem` 与 `GraphicRaycaster` 覆盖真实 UI 命中与拖拽事件，核对已有输入上下文对游戏动作的阻断和恢复。 |
| `content-tools` | 在隔离副本注入配置副本过期、字段错误、缺失键或 Sprite 引用问题，复跑现有配置、迁移、资源、图集和画面检查。 |
| `framework-fixes` | 审查各切片的复现证据。每项确认的公共缺口以具体模块的子任务落实最小修复，提供失败样例、修复后结果和现有调用方回归。 |
| `integration` | 复跑完整用例、注入用例及 Test 原有演示，核对现存问题、证据路径和人工验收项。 |

## 职责和缺口处理

- **Test.Domain 与 Test.Application** 持有格子、合并、伤害、充能、波次与本局流程。BBads 的输入映射、资源键、画质档位与测试场景由 Test 维护。
- **Test 的 Unity 客户端** 组装会话，持有 Prefab、Spine、Canvas 和图集。图形命中、场景节点、GameObject 状态复位和表现暂停在此接线。
- **公共运行时** 维护宿主、时钟、事件、场景、资源、输入和池的通用语义。**Unity 适配** 处理对应的引擎场景操作、主线程、原生对象与输入。**开发工具** 维护迁移、配置、资源、画面检查和工单证据。
- 切片发现失败时记录入口、输入与时间点、预期、实际、日志和负责层。游戏接线在 Test 范围内修复。公共缺口先写入本专项报告，再为复现所指向的模块设定独立写入范围和回归检查。每个假设均记录实际结果，包括现有契约已覆盖的情况。
- 工单通过现有 AgentKit 接手。已有工作区改动进入基线，切片使用各自的证据文件和测试文件。使用关联 worktree 并行时，先确保可用的共同基线包含迁移内容。主 Agent 汇总公共接口变更、组合接线与最终验证。

## 后台验证与人工验收

标准入口执行 `tools/verify.ps1`。真实引擎测试使用 Test 自己的工程副本，以及与其项目声明一致的 Unity 2022.3.16f1，记录实际版本。运行命令需从仓库根目录执行。 [引擎验证](../../../../docs/reference/verification.md)

```powershell
$editor = '<Unity.exe>'
& tools/verify-game-unity.ps1 -Name Test -EditorPath $editor -RunTests
```

按切片传入 `-ResourceSpec`、`-AtlasSpec` 和 `-VisualSpec`。配置和资源故障注入仅在隔离工作区内执行，记录故障报告与恢复后的复跑结果。后台 PlayMode 使用真实场景、资源和事件系统。窗口分辨率、关键 UI 层级、文本和布局可用结构断言，实际像素检查使用可获得的同状态离屏图像或已有后台捕获入口。需要图形设备而暂缺可用后台入口的画面用例单列。 [美术与画面验证入口](../bbads-integration/verification.md)

人工验收时从 `SampleScene` 启动，关闭 `BattleDemoBootstrap` 的自动摆放选项，在 `BBadsBattle` 检查真实鼠标拖拽、多分辨率反馈、Spine 表现，以及暂停恢复的观感。后台注入用例记录发送事件的层级和断言，人工观察记录独立结果。

每张工单交付可重跑步骤、日志或测试报告路径和逐项结论，证据放入 `artifacts`。集成工单汇总本轮基线、公共修复前后证据、Test 两个原有演示的回归，以及待人工项目和启动入口。
