# Test.Server 对战房间

`PvpRealtimeModule` 从 GameHost 的 Tick 驱动 60 Hz 对战，以对局 ID、会话编号和席位校验输入。每位玩家每步最多提交一帧，最多提前 12 步。迟到、重复、乱序和超窗分别确认。

Rain Pass 将本步两份有效输入写入权威帧。遇到缺帧时，移动和持续动作最多沿用 6 步，按键边沿只消费一次。服务端也演算战斗，提供逐帧校验和最终裁决。BBads 由服务端推进准备和战斗，每次下发完整状态。两种模式通常每两步推送一次，发生战斗事件和结算时立即发送。

每个连接保有独立有界队列和连续的 AWRT 序号。每局只结算一次。
